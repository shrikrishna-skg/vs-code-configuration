# Lean execution

Use the small-change workflow in the shared CTO goal policy. Correctness and the user's intended result take precedence over call, time and token targets.

Work directly for small changes. Infer routine design values from the existing scale; ask only about material ambiguity. Inspect the relevant component and shared callers, make the minimum edit, and verify the affected result. A visual change may require a browser measurement or one screenshot even when it has no interactions. Never claim the actual page was verified from a substitute harness.

Reuse existing UI patterns and build interactive UI mockups with HTML/CSS. Generate an image only when the requested deliverable actually needs one and the tool is enabled. Do not repeatedly reload policies, source files or already-passing checks.

Preserve exact workspace paths. Investigate empty listings with a path/type check; never silently trim, rename, delete, or switch folders. Renaming needs explicit authorization and editor/worktree recovery verification.

A 4–8 tool-call target is a checkpoint for small work, not a hard cap. After two failed attempts at the same obstacle, change approach or report the blocker. Retain CTO ownership and report incomplete verification honestly.
