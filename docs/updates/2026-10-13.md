## Verification and limits

The snapshot is checked with `bash scripts/verify.sh`, which now also runs the skim-mode, chat-font and predicted-next-message tests and the extended reapply test.

Bridge checks run on 2026-10-13 against the real CLI:

- The bridge self-test passed, including the warm-process cases against a stub CLI.
- The live check passed on the live bridge: answer, reuse of the same process, recovery after that process was killed, and a fresh process afterwards.
- Eleven behaviour tests passed on spare ports: reuse, idle timeout, the cap, a kill before output (falls back), a kill after output (fails in about 2.5 s instead of hanging), client cancel, recovery after each, a clean shutdown with no stray processes, and the kill switch.
- An independent read-only review found no critical issue.

Limits:

- **Modest gain.** A reused process saved roughly 0.4 to 0.5 s per step on trivial low-effort steps. Step time is dominated by model output at about 95 tokens/s, which none of these changes alters.
- **Small samples.** The timing figures come from a handful of steps, not a benchmark.
- **Not tested:** warm mode with several heavy chats at once. Image steps use the one-shot path by design.
- **Fast mode is off.** It is billed from usage credits rather than the subscription plan, and the account had none.
- **UI patches.** Their automated tests passed in this repository. They were not re-exercised in a live VS Code window as part of this snapshot, and `provider-save-message.test.mjs` needs the installed bundle path.
- Existing windows need **Developer: Reload Window** to pick up UI patches, when running work can be safely interrupted.
